Set up Qwen in OpenCode

Double-click the launcher. A local setup window lets you choose a project, connect Kaggle and follow the real startup log before OpenCode opens.

Windows guided setup · Node.js 20+ · your own Kaggle account · no local AI model

Start with a double-click

  1. Extract the ZIP and double-click Start Qwen OpenCode.cmd. If Node.js is missing, its official installer page opens; install Node.js LTS, then double-click again.
  2. Choose your project folder with the modern Windows Explorer picker, or paste its path. Allow installation for any missing OpenCode and Playwright tools. Browser tools are configured automatically; compatible installed tools are reused.
  3. On the first run, choose Get API token. Sign in, generate a modern API token, then return and paste it into the password field in the local setup window. Windows remembers it encrypted, so later launches skip token entry.
  4. Confirm private cache preparation and GPU use. First setup creates your private model/runtime Dataset using a reusable CPU-only notebook; later setups reuse it. The GPU notebook starts after the cache is ready. The connector starts Qwen, waits until it is ready, and shows the actual startup stages and opens OpenCode in its own terminal. Cancel setup requests shutdown; after OpenCode opens, you can close the setup window.
Prefer a terminal?
node opencode.mjs --setup

Advanced direct-launch options remain in OPENCODE.md inside the ZIP. Add --continue to resume a saved OpenCode conversation.

The Get API token button opens the official token settings page; you control login and token creation. It does not read your clipboard. On Windows, the token is remembered using your Windows account encryption; it is never sent to the model or saved as plaintext. All AI work, including titles and compaction, uses your selected hosted model; Qwen is the default. Local conversations stay separated by project and Kaggle account. Use --forget-kaggle-token to remove the remembered token or --no-remember-token to skip credential storage.

Enter a Kaggle token only in the private local setup window, never in a hosted chat prompt or browser URL. Token entry happens in the private local setup window and is used over HTTPS to start your private notebook. Start Qwen Agent.cmd opens the same guided setup.

Your first task

When OpenCode opens, type this and press Enter:

List the files in this folder and explain what this project does. Don't edit anything yet.

For a browser check, ask: Use the browser to open https://example.com and tell me its heading. Review tool approvals before accepting. Your model is personal-kaggle-qwen/qwen3.8-hauhau; the connector enables only this Qwen provider for every agent. Exit OpenCode when finished to request notebook shutdown.

Optional model link — Hugging Face GGUF only

Leave Model empty for the default Qwen 27B. You can paste a public Hugging Face repository or a complete single .gguf file link. Other model hosts, Ollama library links, private/gated files, safetensors and split shards are not supported. The selected model must support Ollama chat and tool calling, fit the Kaggle GPUs and use a context window of at least 8K. Its revision and checksum are pinned, and context/compaction budgets follow what actually loads. No other model is substituted.

Startup troubleshooting

Unchanged polls no longer flood the log. Queued, running without a startup log, downloading and loading are shown separately using reported notebook status. If a launch limit appears, check active notebooks first. To replace a stale token or use another account: Forget saved token, enter the new token, then retry. A replacement token for the same account does not reset its launch limits or GPU quota.

Weights stored on your PC do not shorten the cloud GPU queue. Each account automatically prepares its own private model/runtime Dataset on CPU before the GPU launch. Later starts reuse ready files, including supported custom Hugging Face GGUFs. The first build needs temporary disk and Dataset storage. GPU queueing and loading still take time.

Visible thinking and automatic compaction

Balanced thinking is enabled and visible by default. Use /thinking to collapse or expand it. Before context fills, OpenCode asks the same hosted Qwen to preserve your task, corrections, files, test results and next steps, then continues automatically. Original conversations remain saved locally. Thinking-only replies can make one automatic finishing pass; repeated size failures stop recovery instead of looping. Compaction extends the conversation across turns; memory and context still have limits.

The connector keeps your notebook online while its window is open, including tool and approval waits. Model requests and startup can wait up to two hours; after a lost connector, a two-hour idle safeguard applies. Kaggle can still enforce its own quota and runtime limits. Close the old connector and relaunch the updated copy once.

The Windows connector runs the native OpenCode 1.19.5 terminal executable. The separate OpenCode Desktop 2 GUI is not supported by this release. Website and local sessions use separate notebooks and histories; running both can use two GPU allocations, subject to Kaggle availability.

Your GPU allowance keeps counting

While your private notebook is allocated, startup, thinking, approval waits, local commands and idle time use your Kaggle allowance. Cancelling an OpenCode task leaves that notebook running.

Exit OpenCode or press Ctrl+C in the connector to request shutdown. Confirm the notebook has stopped in Kaggle. A network failure, closed terminal or crashed PC can delay shutdown; automatic idle shutdown is a backstop.

Each account owns its private caches and GPU notebook; there is no owner-account fallback. Default Qwen remains 27B Q5_K_P at 98,304 context. A selected custom model uses its measured GPU context.

Browser tools, without another setup command

Guided setup includes Playwright browser and search tools automatically. Approve one installation if needed; the launcher then checks an isolated, sandboxed browser before allocating GPU time. Web searches use the browser and your hosted Qwen, with no other AI provider.

Windows prefers installed Chrome, then Edge. Advanced launches can select --with-browser --browser chrome or --browser msedge. Other systems use Chromium. Browser interactions ask for approval. Your existing browser profile and logged-in tabs stay separate. Page text can reach Qwen; screenshot images are omitted from model responses. Temporary browser outputs are removed when the connector closes. Use --setup --no-browser to skip browser tools.

Keep control of your project

Ordinary reads and file discovery can run automatically. Edits, terminal commands, searches, external folders, network requests and browser actions ask for approval; known credential files are denied by the dedicated file rules. Qwen handles the AI work, and OpenCode handles local tools and conversation management.

Approved terminal commands run with your Windows account's permissions. This is an approval policy, not an operating-system sandbox. Relevant project text and tool results pass through the Cloudflare relay to Qwen in your personal Kaggle session. OpenCode history stays on your PC. Context, storage and service/GPU availability have finite limits.
